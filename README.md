# BSRI 性别角色探索测验（贝母量表中文版）

一个**移动优先**的性别角色自我探索网页，基于 Sandra Bem (1974) 的
**性别角色量表（Bem Sex Role Inventory, BSRI）** 编制。60 题 7 点量表，
帮你在「男性化 / 女性化」两个独立维度上看见自己的交织方式，并在
**四象限落点图**上找到自己的位置、看见其他填写者的分布。

线上地址：https://cochranek.github.io/bsri/

## 功能
- 📱 手机友好：单栏响应式、大按钮、进度条
- 🚻 开场只问性别（👦 男生 / 👧 女生），用于落点图配色与对照（男=蓝、女=粉）
- 🧮 原始 BSRI 计分：男性化(M)、女性化(F) 各自 20 题均值，固定分界 5.0
- 🌐 四象限落点图：横轴 M、纵轴 F，5.0 虚线分界；男蓝、女粉
- 👥 可见**其他填写者的落点**：
  - 接入后端时显示**实时真实累积**的全体落点（推荐用 `worker.js`，免费、无需信用卡）；
  - 纯静态（GitHub Pages）时回退到内置**示例分布**（`history.json`，明确标注为演示用，非真实用户），保证始终能看见分布形态
- 🎉 答题鼓励：答到 **1/3、2/3** 时弹出**动态居中的撒花 / 喝彩**提示（不再只是底部小条）
- 📝 暖心 / 启发 / 客观谨慎的四种类型详细解读
- 📸 一键**下载报告截图**（PNG）
- 📥 一键**下载个人作答数据**（JSON，可拿去和其他 AI 深入交流）
- 💡 提醒：下载的数据可直接交给别的 AI，做更深度的对话；点「复制 AI 开场白」会展开并展示可直接粘贴的文案

## 计分与分类规则
| 维度 | 题数 | 计分 |
|---|---|---|
| 男性化 (M) | 20 | 20 题均值（1–7） |
| 女性化 (F) | 20 | 20 题均值（1–7） |
| 中性（填充，不计分） | 20 | 仅用于降低作答偏性 |

7 点量表：1=很不符合，2=基本不是，3=比较不符合，4=说不清，5=较符合，6=基本符合，7=很符合

分类（固定分界值 5.0，维度均值 ≥5 视为该特质「高分」）：
- **双性化**：M≥5 且 F≥5
- **男性化**：M≥5 且 F<5
- **女性化**：M<5 且 F≥5
- **未分化**：M<5 且 F<5

> 标准原版题目按「每 3 题一组（M→F→中性）」循环混合排列，计分一律按类别汇总，与呈现顺序无关。
> 本测验仅供自我探索与科普，**不构成任何临床诊断**。

## 目录结构
```
index.html                单文件前端（内联 CSS/JS，含题项、计分、报告、绘图）
server.py                 可选后端（跨平台）：累积真实落点，提供 /api/submit、/api/points
worker.js                 可选后端（Cloudflare Worker + KV，免费无需信用卡）：同样的接口，适合无服务器托管真实落点
assets/data/history.json  内置示例分布（纯静态部署时的回退数据源，明确标注为演示用）
requirements.txt          server.py 依赖（flask）
.gitignore                运行期 data/ 与 Python 缓存不入库
```

## 本地预览（纯静态，无后端）
```bash
python3 -m http.server 8000
# 浏览器打开 http://localhost:8000
```
此时落点图会使用内置匿名样本，仍可完整体验。

## 本地运行（带真实后端，累积真实落点）
```bash
pip install -r requirements.txt
python server.py                 # 默认 http://0.0.0.0:8000
PORT=9000 python server.py       # 自定义端口
```
后端把每个填写者的 (M, F, 性别, 类型) 落点写入 `data/points.json`
（该目录已被 .gitignore 忽略，不入库），并通过 `/api/points` 返回全体落点。
前端优先用真实后端；若后端不可用（如 GitHub Pages 纯静态），
自动回退到 `assets/data/history.json` 的匿名样本，保证始终可见他人分布。

## 部署
- **GitHub Pages（纯静态，开箱即用）**：把 `index.html`、`assets/data/history.json` 推到
  `main` 分支根目录即可。此时落点图使用内置**示例分布**（演示用），适合先看效果 / 挂链接。
- **带真实后端（推荐，显示真实落点）**：二选一——
  - 简单托管：在本机 / 云服务器运行 `server.py`，把 `index.html` 顶部的
    `const API_BASE = ''` 改成后端地址，即可累积并显示真实全体用户的落点。
  - **零成本无服务器（推荐，本项目已部署）**：用 `worker.js` 部署到 Cloudflare Workers（免费、无需信用卡），
    绑定一个 KV 命名空间后，把 `API_BASE` 改成 Worker 域名即可。本项目已部署后端：
    `https://polished-moon-b698.cunyikang.workers.dev`（KV 命名空间 `bsri-points`）。
    前端 `API_BASE` 已指向它，每位真实填写者的落点都会被累积，前端读取的是**真实全体分布**，而非示例。
    需要重新部署后端时，运行 `bash cf_deploy.sh`（需先设置环境变量 `CLOUDFLARE_API_TOKEN`）。

### 每人「详细作答」独立存储 + 仅本人可取回
- 除了散点图用的聚合落点，后端还会**匿名存每个人 60 题的完整作答**：
  每次提交前端生成随机 `uid`（存浏览器 localStorage，即「数据提取码」），连同 60 题打分一起发到
  `POST /api/submit`；后端用 KV 键 `resp:<uid>` 单独保存这份明细（含 m/f/类型/性别/作答数组/时间戳）。
- **「每个用户只能下载自己的数据」**：前端「下载我的数据」按钮调用 `GET /api/mine`（头部带
  `x-bsri-uid` 或 `?uid=`），后端只返回该 `uid` 对应的明细，他人（不知道 uid）无法取回。
  uid 是 128 位随机串，不可猜；全程**不存姓名 / 微信 / IP**，匿名且隐私安全。
- 换手机或清缓存后，凭结果页展示的「数据提取码」仍可取回自己的数据。
- 后端接口：`GET /api/points`（全体落点）、`POST /api/submit`（写落点+明细，返回 uid）、
  `GET /api/mine`（凭 uid 取回本人明细，404=无记录）。
